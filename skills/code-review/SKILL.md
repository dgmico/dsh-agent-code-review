# 代码审核清单

先确定范围与意图，再按维度逐项排查。只报能落到 `文件:行号` 的问题；每个维度都不是必须产出结论，没发现问题就跳过。

## 0. 前置事实

- 改动清单：`git diff <base>...HEAD`、`git diff --stat`、`git log --oneline <base>..HEAD`；无 git 时按用户指定的文件范围。
- 期望行为与验收标准：需求/PR 描述、测试、类型定义、仓库约定（AGENTS.md、CLAUDE.md）。
- 影响面：谁调用被改的代码（按符号名 grep）、被改代码调用谁、是否存在跨进程或跨版本契约。

## 1. 正确性

- 边界与取值：空集合、单元素、超长输入、Unicode、时区、浮点比较、整数溢出、零与负数。
- 分支覆盖：提前返回、异常路径、默认分支、穷尽性检查缺失（switch/模式匹配漏项）。
- 状态与顺序：非法状态转换、重复初始化、幂等性、重入、乱序到达。
- 时间语义：单调时钟 vs 墙钟、超时、重试是否幂等、本地时间与 UTC 混用。
- 典型笔误：条件取反、变量用错、单位/量纲、off-by-one、复制粘贴未改全。

## 2. 安全

- 注入：SQL/命令/模板/日志注入、路径穿越、不安全反序列化、SSRF、XSS。
- 信任边界：外部输入是否校验（类型、长度、范围、编码），校验是否发生在正确的层。
- 认证授权：每个入口是否都做身份与权限检查、越权（IDOR）、权限提升、默认拒绝。
- 秘密与隐私：硬编码凭据、错误信息与日志泄露敏感数据、PII 落盘或外发。
- 密码学：弱算法、固定 IV/salt、以非密码学随机数用于安全场景、关闭证书校验。
- 依赖风险：新增依赖的必要性、版本范围、已知漏洞（必要时联网核对）。

## 3. 数据与一致性

- 事务边界：原子性、部分失败、并发写、丢失更新。
- 迁移与 schema：向前/向后兼容、回滚路径、大表锁与耗时、新列默认值。
- 缓存：键设计、失效策略、陈旧读取、缓存击穿与竞态。
- 序列化契约：字段增删的兼容性、必填/可选、版本协商。

## 4. 并发与资源

- 共享可变状态：锁的粒度与获取顺序、死锁、无锁假设是否真的成立。
- 异步：漏 `await`、未处理的 Promise、取消传播、检查后使用（TOCTOU）竞态。
- 资源：文件/连接/句柄/订阅是否在**所有**路径释放（含异常路径）、泄漏、无界队列与内存增长。

## 5. 错误处理与可观测性

- 错误是否被吞掉（空 catch、忽略返回值）、原因链是否丢失。
- 对用户与对日志的暴露面是否恰当：可诊断，但不泄密。
- 失败是否可恢复：重试、退避、熔断、降级、幂等。
- 关键路径是否有足够的日志与指标定位问题，级别是否正确。

## 6. 接口与兼容性

- 公共 API / 配置 / CLI / 协议变更是否破坏调用方，是否有弃用与迁移路径。
- 默认值变更、语义变更、错误码变更。
- 类型是否真正约束运行时：`any`、断言、schema 与实现是否一致。

## 7. 性能

- 复杂度与规模：热路径上的 O(n²)、N+1 查询、无界循环。
- IO：批量化、连接复用、超时、背压；是否在锁内做 IO。
- 内存：大对象复制、无上限缓存、流式处理是否正确缓冲。

## 8. 测试与可验证性

- 新行为是否有测试、断言是否真的会失败、边界与失败路径是否覆盖。
- 是否被 mock 掩盖了真实的集成风险。
- 本地可跑的验证命令：测试、类型检查、lint、构建；报告命令与输出原文。

## 9. 可维护性（低优先）

- 命名与结构是否与仓库既有约定一致、重复实现、隐藏耦合、注释与实现不符。
- 仅在明显违反仓库约定或影响正确性理解时上报。

## 分级标准

- 阻塞：导致错误结果、数据损坏、安全漏洞、线上事故，或破坏兼容性且无迁移路径。
- 重要：特定条件下出错或明显退化，应在合入前修复。
- 次要：真实但影响有限，可随后修复。
- 建议：风格、结构、可读性改进。

## 反模式（不要这样报）

- 不报无法落到具体代码位置的「最佳实践」。
- 不把「可能有」的猜测写成结论；放进存疑清单。
- 同一根因的多个表象合并为一条，列出全部位置。
- 不评审与本次改动无关、也未被本次改动触发的历史代码。
- 没有实际运行，就绝不声称测试或检查通过/失败。
